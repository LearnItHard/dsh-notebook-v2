## 0. 直接回答：要不要建 codebase（项目级索引/RAG）？

**不要。至少当前阶段不要，三个硬理由：**

1. **场景不匹配**。notebook 补全失败的头号原因是「模型不知道 `df` 有哪些列、上面 import 了什么」，
   不是「不知道项目里 `utils.py` 有个函数」。前者已经被**内核变量 + 前序格**覆盖（都已上线）。
   Tabby 做仓库索引（tree-sitter + BM25 + token 倒排）是因为 IDE 场景跨文件引用密集；
   数据分析 notebook 的引用闭包大头在 notebook 内部和内核运行时里。
2. **延迟预算装不下**。ghost 可用窗口约 300ms–1s（Zed 验收线 p50<200ms / p90<500ms；
   我们用通用 chat 模型本来就要 0.8–2s）。RAG 检索 + 拼片段再加 100–300ms 和成百上千 token，
   还会挤占 prefix/suffix 的预算（Continue 的分配：1024 token 中 prefix 30% / suffix 20% / 上下文 50% 封顶）。
3. **已有更好的替代通道**。需要项目级上下文的改写走 `buildChatPrompt()` 投进主对话
   （2026-11-06 实测定案的 `inputActions` 通道），主对话 agent 有完整工作区 + `nb_*` 工具 ——
   显式、按需、完整，比在补全 prompt 里塞检索片段可靠得多。

**什么时候重新考虑**：如果用户开始大量 `from utils import ...` / `from .xxx import ...`
（notebook 引用同目录本地模块），再做一个**极简中间层**就够：
请求时按 import 行解析相对路径，把目标 `.py` 的**函数/类签名清单**（不含函数体，
每文件 ≤500 字符、最多 2 个文件）塞进上下文 —— Continue「import 符号上下文」的缩水版，
不建索引、不解析 AST、不做向量库。触发条件出现前不预建。

**明确排除**（维持调研结论）：#18 NES（专模型 + 编辑会话数据 + 投机解码，我们做不了）、
#19 仓库级 RAG、逐 token 流式 ghost、默认多候选、用 FIM 特殊 token 拼通用 chat 模型。

## 2. 实施批次（每批独立验收，按性价比排序）

### 批次 A —— 成本与手感收尾（约 1 天，3 项全 S）

1. **#2' 缓存最长前缀匹配**：`cacheGet` 改为遍历找「最长 key 使 `doc.startsWith(key)` 且
   `suggestion.startsWith(doc.slice(key.length))`」，命中返回 `suggestion.slice(...)`。
   key 保持 `pos\0doc` 但匹配时只比 doc 前缀。64 条内存版够用，不落 SQLite。
2. **#14 stop + max_tokens**：`index.js` 的 ghost 路由传 `maxTokens ≈ 150`、
   `stop: ["\n\n\n", "\n#", "\n%%"]`（在 `streamOpts` 上，宿主不支持的字段要容错忽略）；
   提示词侧补一句「至多 6 行」。
3. **#4 按行接受**：`suggestion.slice(0, indexOf("\n")+1)`，剩余建议 `pos` 同步平移
   （照抄 `acceptWord` 结构）；命令 `ghost.acceptLine`，键位 `Ctrl-End` 或 `Alt-]` 待定。

**验收**：① 打 `df.he` → 出建议 → 退格到 `df.h` → 再敲 `e`，**0 网络请求**恢复同一建议；
② 单次 ghost 输出 ≤6 行、无整格重吐；③ 按行接受后剩余建议仍在正确位置。

### 批次 B —— 质量（约 1–2 天，3 项）

4. **#8 跨格上下文 v2**：markdown 格取「标题行 + 首行文本」当意图注释（每格 ≤120 字符）；
   代码格保持尾部截断但按**总预算 1200 token** 从近到远填充（不再固定 3 格）；
   上下文面板（`ctx: {neighbours, vars, error}`）如实计数。
5. **#6 过滤器 v1**：`shouldRequestCompletion` 从 0/1 改打分制，加两个特征 ——
   「上次建议被 Esc 拒绝后 3s 内降权」「光标前字符白/黑名单」（抄 Copilot 逆向的权重方向：
   刚开括号加分、刚闭合减分）。阈值可配。
6. **#13 设置项**：`aiPrefs.completion` 增加 `debounceMs`（默认 550）/ `maxLines`（默认 6），
   改动即生效不刷新。

**验收**：① markdown 格「## 数据清洗」出现在 ghost 提示词上下文里（后端 debug 回显验证）；
② Esc 拒绝后立刻打字不触发新请求，3s 后恢复；③ 设置面板两项可改、立即生效。

### 批次 C —— 呈现加固（约 2 天，可选，2 项）

7. **#10 多行加固**：`maxLines` 截断 + 超出折叠；多行 ghost 用 block widget 或行高预留，
   不把下方内容推走（先真机确认现在的渲染形态再选方案 —— 调研 §5 第 7 条的不确定性还在）。
8. **#11 增量收缩**：`docChanged` 时若插入文本恰是建议前缀，`slice` 后退而非清空
   （JupyterLab `FilterAndUpdate` 逻辑）；删除/替换仍清空。

**验收**：① 10 行建议折叠为 6 行 + `⇓`；② 逐字敲出建议内容时幽灵逐字后退不闪没。

### 观察项（暂不做，触发条件写了再做）

- **本地模块签名注入**（§0 中间层）：触发条件 = 用户 notebook 里出现本地 `from xxx import` 的抱怨/案例。
- **多候选轮换**（#16）：只在 `Alt-\` 手动触发时请求 2–3 条（JupyterLab 语义），自动触发永不。
- **流式 ghost**（#15）：等 `llm.stream` → NDJSON → CM widget 三处都有把握再动。

- 全部改动集中在 `lib/client.js`（单文件 CJS 工厂，不能 import 兄弟文件）+ `lib/ai.js` + `lib/index.js`；
  纯函数挂 `module.exports.__internals`，测试进 `test/client-logic.mjs` / `test/ai.mjs`。
- 改完 `node --check lib/client.js` + `node test/all.mjs --fast`；宿主半改 `lib/index.js` 要重启应用。
- 任何「不发请求」的判据改动都要防「永远不补」回归：`shouldRequestCompletion` 有矩阵测试，

### 5.2 与计划的偏差（有意为之）

- **`(` `,` `=` 不能当加分特征**：它们已被「只打了运算符就等用户写完」的硬门槛一票否决，
  写进白名单也**永远走不到**（评审提过：不可达判据等于没写）。改用 `.`（属性访问）与 `:`（块开始）。
- **`Ctrl-End` 也绑了按行接受**：没有建议时返回 false，会落到 `CM.defaultKeymap`，
  正常编辑里「跳到文末」不受影响；有建议时才有副作用 —— 这是给「不想记 Alt-]」的人留的入口。
- **debug 回显**：`POST /nb2/ai/complete {debug:true}` 会带上 `debug.messages`（真正拼出来的提示词）
  与 `context/contextChars/vars` 计数。验收「markdown 意图进上下文」不必再靠猜；
  正常请求**不回显**（提示词里有用户代码，不往网络多送一份）。
